# glilmi — 売上目標レポートの作成・推敲

ユーザーが `/glilmi` を明示したときだけ使う。テーマは固定で次のとおり。

**課題：** 売上目標を絶対に達成するために私ができること

## モード判定

| 状況 | モード |
|------|--------|
| 下書き・既存ファイルの修正依頼 | **推敲** |
| 「書いて」「作成して」「草案を」など、下書きがほぼない | **作成** |
| どちらとも取れる | ユーザーに一言確認してから進む |

両モードとも、下記の**固定テンプレ・ルール・文体**を守る。過去レポート（`レポート/2025_04.md`・`レポート/2026_07.md`）の文体を参考にする。

---

## 作成モード

ゼロまたは箇条書きメモから、提出用の草案を書く。

### 手順

1. 保存先を決める。指定がなければ `レポート/YYYY_MM.md`（当月）。既存ファイルがある場合は上書き前に確認する。
2. 材料を集める。次が足りないときは、**最大2点だけ**質問してから書く（全部揃うまで待たない）。
   - 現場で感じている課題（売上・満足・稼働に効きそうなこと）
   - 自分がやる具体アクション（1〜3個）
3. 材料が少ない場合は、過去レポートと担当範囲（清掃・荷物運び・館内接客など）から**妥当な草案**を出し、「要確認」の箇所を短く示す。現場の固有事実は捏造しない。
4. 固定テンプレで Markdown を書き、ファイルに保存する（またはチャットに完成稿を出す）。
5. 作成後は、構成の要点と「ユーザーに確認してほしい点」を箇条書きで短く伝える。

### 作成時の材料の例（ユーザー入力の受け方）

雑なメモでも受け取る。例：

```
・清掃の遅れでチェックインに響くことがある
・荷物の取り違え防止をもっと徹底したい
・館内ですれ違うときの挨拶を揃えたい
```

これをテンプレの①②③に落とし、各項目に売上・満足への接続文を付ける。

## 推敲モード

下書きを受け取り、**構成・具体性・社内提出向けの表現**を整える。

### 手順

1. 下書き（チャット本文・指定ファイル）を読む。未指定なら `レポート/` 内の該当月ファイルを確認する。
2. 固定テンプレに沿って推敲し、指定ファイルがあればそこに書き戻す。なければ推敲結果を提示する。
3. 推敲後は、変えた点を箇条書きで短く伝える（長文の再説明はしない）。

---

## 固定構成テンプレ

見出し番号・役割は原則このまま使う。ユーザーが「結論なし」などと指定した場合のみ省略する。

```markdown
# 売上目標達成のために私ができること

## 1. 現状の課題認識：（現場で感じている、売上に効く論点を一言）

（売上・稼働・満足度・リピート・口コミなどに関わる現状。自分の担当範囲＝清掃・荷物運び・館内接客などから書く）

## 2. 売上目標達成のために私ができること

### ①：（自分ができる具体アクション名）

（何をするか → それが売上・満足・効率のどれにつながるか）

### ②：（自分ができる具体アクション名）

### ③：（任意。2つでも可）

## 3. 取り組みの進め方と確認の仕方（任意）

（いつから／誰と／どう効果を見るか。大きな約束は避け、自分が回せる範囲に落とす）

## 結論（任意）

（「私ができること」に戻して1段落で締める）
```

## 「私ができること」に絞るルール

- **主語は自分。** 「会社が〜すべき」「経営は〜」ではなく、「私は〜する／促す／整える／提案する」。
- **権限外の施策は書かない。** 価格改定・大規模投資・他部署の強制異動などは、自分ができる範囲（情報共有・現場の型・備品洗い出し・挨拶品質など）に言い換える。
- **売上との接続を一文入れる。** 各施策の末尾で、次のどれか（または複合）に触れる。
  - 客室回転・清掃の遅れ解消 → チェックイン体験・稼働への影響
  - 備品不足・ミス・やり直し削減 → クレーム予防・口コミ
  - 接客・挨拶・荷物運びの丁寧さ → 満足度・リピート
  - ムダ時間の削減 → 接客や改善に回せる余力
- **抽象スローガンだけで終わらせない。** 「意識する」「頑張る」は不可。観察・リスト化・型の共有・声かけの定型・確認タイミングなど、行動に落とす。
- **過去レポートと重複しすぎない。** 合理化・標準化の話を再利用する場合は、「それが売上達成にどう効くか」を正面に据え直す。

## 社内提出向けの文体

過去レポートに合わせる。

- です・ます調。断定しすぎず、「〜と考えています」「〜ではないかと捉えています」を適度に使う。
- 重要語句のみ `**太字**`。多用しない。
- 箇条書きは原因・手順・施策の列挙に使う。本文は短段落でつなぐ。
- 個人攻撃や他部署批判は避ける。「人の問題」ではなく「仕組み・工程・共有不足」に寄せる。
- 絵文字・装飾過多・ビジネス書調のキャッチコピーは使わない。
- 虚偽の数値・未確認の実績は書かない。材料に数字がなければ無理に作らない。

## チェックリスト（作成・推敲共通）

- [ ] タイトル／冒頭が課題「売上目標を絶対に達成するために私ができること」に対応している
- [ ] 各施策の主語が自分になっている
- [ ] 各施策に「何をするか」と「売上・満足・稼働のどれに効くか」がある
- [ ] 抽象語だけで止まっている箇所がない
- [ ] 権限外の大改革になっていない
- [ ] 過去レポート（合理化・標準化）の焼き直しだけになっていない
- [ ] 社内提出として読んで違和感のない敬体・段落構成になっている

## 出力の扱い

- 作成：原則 `レポート/YYYY_MM.md` に保存。既存内容がある場合は上書き前に確認。
- 推敲：指定ファイル／該当月ファイルへ反映。下書きのみなら Markdown で返す。
- ユーザーの事実・現場感を優先する。推測で現場の詳細を捏造しない。
